# TalentNfcReader_CST820 — LILYGO T-RGB(2.1" 원형) 판 NFC 키링 리더

[`../TalentNfcReader`](../TalentNfcReader/README.md) 를 **둥근 화면이 붙어 나오는 기성품
보드**로 옮긴 것이다. 하는 일과 화면 흐름은 원본과 같으므로 동작 설명은
[원본 README](../TalentNfcReader/README.md) 를 본다. 이 문서는 **다른 점만** 적는다.

같은 리더의 다른 보드 판인 [`../TalentNfcReader_JC3245`](../TalentNfcReader_JC3245/README.md)
(가이션 3.5" 네모 화면)와는 화면 계층(`PanelTFT.h/.cpp`)만 다르고 나머지는 같다.

| | 원본 TalentNfcReader | 이 폴더 |
|---|---|---|
| 보드 | ESP32-S3-DevKitC-1 + 손배선 | LILYGO T-RGB (ESP32-S3R8, 플래시 16MB · PSRAM 8MB) |
| 화면 | 2.8" 240×320 ILI9341 (SPI) | **2.1" 480×480 원형** ST7701S (RGB 병렬, 붙박이) |
| 화면 명령 | SPI 직결 | I2C 확장칩(XL9535)을 거친다 |
| 터치 | XPT2046 저항막 (보정 필요) | 정전식 CST820 — I2C 0x15 (보정 없음) |
| 그리는 라이브러리 | TFT_eSPI | Arduino_GFX + 이 폴더의 껍데기 |
| 손으로 잇는 것 | 화면 14선 + PN532 + 부저 | **PN532 넉 선뿐** |
| 백라이트 | PWM | 16단계 펄스(보드 방식) |
| 소리 | 피에조 부저 | 없음 |

## 배선

화면·터치·백라이트는 보드 안에 붙박이다. 옆면 1.25mm **IIC/UART 커넥터** 넉 선에
PN532 만 잇는다.

```
  보드 IIC 커넥터        PN532 (I2C 모드)
    3V3    ───────────   VCC
    GND    ───────────   GND
    GPIO8  ───────────   SDA
    GPIO48 ───────────   SCL
```

이 I2C 버스에는 터치(0x15)와 화면 확장칩(0x20)이 이미 붙어 있지만 PN532 는 0x24 라
주소가 겹치지 않는다 — **그냥 같은 버스에 물리면 된다.** (JC3245 판은 터치가 다른
칩이라 버스를 나눴지만 여기서는 나눌 이유가 없다.)

PN532 모듈의 작은 스위치는 **I2C 자리**에 둔다(보통 1:OFF, 2:ON).

### 보드가 쓰고 있는 핀 (건드리지 말 것)

| 핀 | 쓰임 |
|----|------|
| 45 · 41 · 47 · 42 | RGB 타이밍 (DE · VSYNC · HSYNC · PCLK) |
| 21 · 18 · 17 · 16 · 15 / 14 · 13 · 12 · 11 · 10 · 9 / 7 · 6 · 5 · 3 · 2 | RGB 색 데이터 16선 |
| 46 | 백라이트 (16단계 펄스) |
| 8 · 48 | I2C — 터치 · 확장칩 · (우리가 다는) PN532 |
| 1 | 터치 INT — 딥슬립에서 화면을 눌러 깨울 때 쓴다 |
| 39 · 40 · 38 | TF 카드 (쓰지 않는다) |
| 4 | 배터리 전압 측정 (쓰지 않는다) |

화면 켜는 명령선(CS · SDA · CLK · RST)과 전원 인에이블은 **ESP32 핀이 아니라 XL9535
확장칩의 핀**이다(각각 3 · 4 · 5 · 6 · 2번). Arduino_GFX 의 `Arduino_XL9535SWSPI` 가
그쪽으로 명령을 넣어 준다.

## 둥근 화면에 네모 화면을 올린다

이 기기는 지름 480 의 **원형**이다. 원본 리더의 화면은 네모라 그대로 올리면 네 귀퉁이가
잘린다. 그래서 원 안에 들어가는 가장 큰 정사각 **338×338** 을 잡아, 본체에는 그것을
'화면' 이라고 알려 준다. 껍데기가 그리는 좌표와 터치 좌표를 가운데로 옮겨 주고,
정사각 밖(둥근 테두리)은 바탕색으로 채운다. 그 밖을 누른 것은 누르지 않은 것으로 친다.

`PanelTFT.h` 의 `TR_UI_W`·`TR_UI_H` 가 그 정사각이다. 줄이면 테두리 여유가 늘고,
늘리면 네 귀퉁이가 잘리기 시작한다.

### 화면이 작다

셋을 나란히 재 보면 이렇다(계산값).

| 판 | 내용 높이 | 내역 줄 수 | 화면 실물 | 본문 글자 | 이름 글자 |
|----|-----------|-----------|-----------|-----------|-----------|
| 원본 2.8" | 270 | 8줄 | 42.6 × 56.8 mm | 2.5 mm | 3.6 mm |
| JC3245 3.5" | 416 | 10줄 | 49.3 × 73.9 mm | 3.1 mm | 3.7 mm |
| **이 판 2.1" 원형** | 274 | **6줄** | **37.7 × 37.7 mm** | 2.2 mm | 2.7 mm |

세로로 쓸 수 있는 픽셀은 원본과 비슷하지만 **실물이 작다.** 글자를 더 키우고 싶으면
32px 한글 폰트를 구워 `useFont(20)` 자리에 끼우면 된다(그만큼 줄 수가 준다):

```bash
python3 tools/ttf2vlw.py ~/Library/Fonts/NanumGothicBold.ttf --size 32 --ks2350 \
    --preset ui --chars "·" --var FontKR32 -o TalentNfcReader_CST820/FontKR32.h
```

줄 세우기용 사진(208px)은 세로 208 자리에 딱 맞게 들어간다 — 여유가 없으므로
띠 높이(`HEAD_H`·`BTN_H`)를 키우면 사진이 빠지고 글자 모양으로 떨어진다.

## 빌드

```bash
./TalentNfcReader_CST820/build.sh            # 컴파일
./TalentNfcReader_CST820/build.sh --upload   # 컴파일 + 업로드
```

**PSRAM(opi)을 반드시 켜야 한다** — RGB 화면의 프레임버퍼 460KB(480×480×2)를 거기에 잡는다.
파티션은 원본과 같은 표(앱 4MB + LittleFS 11.875MB)를 쓴다.

```bash
arduino-cli lib install "GFX Library for Arduino" "Adafruit PN532" "ArduinoJson" "NimBLE-Arduino"
```

폰트 헤더는 저장소에 없다(파생 파일). 클론 직후 `./tools/make-fonts.sh` 를 한 번 돌린다.

현재 크기: 플래시 3,655,139B(3.66MB) / 앱 칸 4MB · 전역 108,500B.

### USB 케이블

이 계열 보드는 **A to C 케이블**을 쓴다. C to C 케이블로는 맥이 보드를 알아보지 못한다
(Type-C 단자에 CC 저항이 없어서다). 포트가 `/dev/cu.usbmodem*` 으로 잡히지 않으면
케이블부터 본다.

## 화면을 어떻게 그리는가

RGB 병렬 화면은 TFT_eSPI 가 다루지 못한다. 그리는 일은 Arduino_GFX 가 맡고, 본체가
부르는 `tft.*` 는 같은 이름의 껍데기가 받는다.

| 파일 | 하는 일 |
|------|---------|
| `PanelTFT.h/.cpp` | `tft.*` 를 Arduino_GFX 로 옮겨 준다. 좌표를 원 가운데로 옮기고, 터치(I2C)와 백라이트도 여기서 다룬다 |
| `VlwFont.h/.cpp` | 한글 스무스폰트(VLW)를 직접 읽어 글자를 그린다 (JC3245 판과 같은 파일) |

JC3248 판과 달리 **미는 태스크가 없다.** RGB 패널은 PSRAM 의 프레임버퍼를 LCD 가 계속
읽어 뿌리는 구조라, 버퍼에 그리면 그대로 화면이 된다.

백라이트는 PWM 이 아니다. 핀을 짧게 흔든 횟수로 16단계 중 하나를 고른다(LILYGO 방식).
서버 설정의 밝기(0-255)를 그 16단계로 바꿔 넣는다 — `tft.setBacklight()`.

## 실기에서 확인한 것

2026-09-16 LILYGO T-RGB 2.1" 원형(CST820)에 구워 봤다(3,655,347B).

- 화면(초기화 표 `st7701_type4`)·색(바탕 주황 — R/B 뒤집힘 없음)·둥근 테두리 안 정사각 배치 정상
- 터치 좌표 방향 정상 — 누른 자리에 점을 찍어 맞춰 봤다(뒤집기·맞바꾸기 필요 없음)
- 와이파이 연결 → 서버 설정 받기 정상

### 겪은 문제

**1. 글자 일부가 깨진다('건너뛰기').** RGB 화면은 프레임버퍼를 PSRAM 에서 **직접** 읽어 간다.
Arduino_GFX 는 그릴 때마다 캐시를 PSRAM 으로 밀어 주지만(`Cache_WriteBack_Addr`), 글자는
우리가 버퍼에 바로 써서 그 일을 안 했다 → 글자 픽셀 일부가 캐시에만 남았다.
→ 글자를 다 그린 뒤 `flush(true)` 로 밀어 준다.

**2. 터치가 전혀 안 된다 — 원인이 둘이었다.**
- CST820 의 리셋이 ESP32 핀이 아니라 **확장칩(XL9535)의 1번(TP_RES)** 에 붙어 있다.
  켜면 리셋에 잡힌 채라 I2C 에 아예 안 나온다(0x20 만 보였다) → 1번을 내렸다 올린다.
  자동 잠들기(0xFE)도 끈다.
- **내장 LED 코드가 I2C 를 깨뜨렸다.** 코어의 esp32s3 변형이 `RGB_BUILTIN` 을 GPIO48 로 두는데,
  이 보드에서 48번은 **I2C SCL** 이다. 부팅 직후 상태 LED 가 그 핀을 흔들어, 터치가 한 번
  응답하고 그 뒤로 NACK(err=2)만 났다 → 이 스케치에서는 LED 를 자동으로 잡지 않는다.

### 아직 확인하지 못한 것

1. **PN532** — 아직 붙여 보지 않았다. 옆 4핀 커넥터(G·SCL·SDA·3V3)에 잇고 시리얼에
   펌웨어 판 번호가 찍히는지 볼 것. 터치와 같은 I2C 버스라, 안 되면 PN532 를 뺀 채
   터치가 여전히 되는지부터 갈라 본다.
2. **헤더 띠 한 번·두 번 누르기** — JC3248 판처럼 한 번이 두 번으로 세어지지 않는지.
3. **글자 크기** — 실물을 보고 더 키울지 정한다.
4. **딥슬립 기상** — `sleepEnabled` 를 켠 기기에서 화면을 눌러 깨어나는지(GPIO1).
