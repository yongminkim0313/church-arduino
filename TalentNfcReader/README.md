# TalentNfcReader — ESP32-S3 NFC 키링 리더 (펀펀포인트)

NTAG-213 키링을 PN532(I2C)로 읽어 2.8" ILI9341 TFT 에 포인트를 보여준다.
입력은 디스플레이에 붙은 XPT2046 터치 패널 하나뿐이다.

화면 미리보기: [`../TalentNfcReader.html`](../TalentNfcReader.html) — 브라우저에서 열면
탭 전환·태깅·오류 화면을 실제 렌더링 그대로 만져 볼 수 있다.

## 처리 순서

"누구에게" 와 "무엇을 얼마나" 를 **NFC 두 장**으로 나눠 받는다. 어린이 키링이 "누구",
지급/사용 카드가 "무엇을 얼마나" 다.

```
대기 ── 키링 ──▶ 사람 ── 확인 ──▶ 카드 대기 ── 카드 ──▶ 완료 ──(doneMs)──▶ 대기
              이름·잔액            등록된 카드          그림·얼마
              ·최근 내역           목록                 ·남은 포인트
```

한 번에 처리하지 않는 이유: 잘못 댄 키링을 **되돌릴 자리**가 있어야 한다. 예전에는
태깅 한 번으로 곧바로 잔액이 움직여서, 틀리면 관리자가 화면에서 손봐야 했다.

되돌릴 자리는 **사람 화면 한 곳**이다. 카드를 댄 뒤에는 다시 묻지 않는다 —
확인할 것(누구에게)은 이미 보고 눌렀고, 무엇을 얼마나는 카드에 적혀 있어 고를 여지가
없다. 줄을 세워 놓고 쓰는 기기라 누르는 횟수가 하나 줄면 체감이 크다.

**사용에서 잔액을 넘으면** 카드를 댄 자리에서 막고 "포인트가 모자랍니다" 를 띄운다.
카드 단계에 그대로 머물러 다른 카드를 대면 된다.

| 동작 | 결과 |
|------|------|
| 키링 태깅 | 이름 · 남은 포인트 · 최근 내역을 띄우고 **확인**을 기다린다 |
| 확인 (사람 화면) | 카드 대기로 넘어간다. **출석모드**면 이때 곧바로 지급된다 |
| 카드 태깅 | **곧바로 처리**하고 완료 그림을 띄운다 (`doneMs` 뒤 저절로 대기로) |
| 위쪽 탭 터치 | **지급 / 사용** 전환 — 진행 중이던 것은 접힌다 |
| **헤더 띠 터치** | 전체 내역으로. 다시 누르면 원래 탭으로 돌아온다. 여기서 키링을 대면 잔액을 건드리지 않고 조회만 한다 |
| 내역 탭 위·아래 띠 터치 | 위 = 이전 페이지(더 최근), 아래 = 다음 페이지(더 예전) |
| 60초 무입력 | 진행 중이던 것을 스스로 접는다 — 앞사람 이름에 다음 사람이 처리되는 사고 방지 |
| 무입력 | `sleepEnabled` 가 켜진 기기만 딥슬립 (기본 꺼짐) |

### 켤 때 뜨는 화면

전원을 넣고 서버에 붙기까지 몇 초 동안 뜬다. 화면 전체를 덮으므로 **테두리·헤더·탭
버튼을 그리지 않는다** — 아직 아무것도 고를 수 없는 상태라 단추가 있으면 눌러도 되는
줄 안다.

이 그림만 예외적으로 **파일 이름을 NVS 에 들고 있는다.** 서버에 붙기 *전에* 그려야
하는데, 그때는 설정을 아직 못 받았기 때문이다. 그래서 **그림을 바꾼 뒤 한 번은 예전
그림이 뜬다**(그 부팅에서 새로 받고, 다음 부팅부터 새것). 처음 켤 때는 아직 아무것도
없어서 바탕색에 "연결 중" 글자 한 줄로 대신한다.

### 헤더 띠

로고·제목·연결 표시가 들어가는 맨 위 띠다. **띠 전체가 내역 단추**다 — 작은 아이콘
하나보다 훨씬 누르기 쉽고, 관리자가 올린 띠 그림에 자리를 뺏기지도 않는다. 다시 누르면
원래 탭으로 돌아온다(들어가는 문과 나오는 문이 같아야 헤맬 일이 없다).

관리자 화면에서 **연결됨·끊김 두 장**을 올리면 그 그림이 띠 전체를 대신한다. 한 장만
올리면 쓰이지 않는다 — 연결이 끊겼을 때 화면이 비어 무슨 일인지 알 수 없기 때문이다.

탭 줄의 빈자리(버튼 둘레)도 내용 영역과 같은 바탕색으로 칠한다. 흰 띠로 두면 버튼
위아래에 흰 줄이 남아 화면이 세 토막으로 끊겨 보인다.

### 지급/사용 카드

`GET /api/talent/cards` 로 부팅할 때 받아 둔다. 카드 한 장은 `{ uid, side, name, amount, category }`
이고, 관리자 화면(**지급 · 사용 카드**)에서 등록한다. 여러 장 등록할 수 있다.

**금액은 리더가 정하지 않는다.** 처리할 때 `POST /earn|/spend` 에 `card` UID 만 보내고,
서버가 그 카드에서 금액·이름·분류를 찾아 쓴다. 리더는 현장에 놓인 기기라 요청을 흉내
내기 쉬워서, 오르내리는 양의 근거를 서버에만 뒀다.

기기 모드(`modeLock`)와 맞지 않는 카드는 거절한다 — 지급 리더에 간식 카드를 대는 사고를 막는다.

### 처음 보는 카드

예전에는 모르는 UID 에 곧바로 잔액을 만들었다. 그래서 휴대폰이나 교통카드가 스쳐도
"이름 없는 사람" 이 생겼다. 이제는 **아무것도 만들지 않고** `POST /api/talent/seen` 으로
알리기만 한다. 관리자 화면의 **미등록카드** 팝업에 **새로고침 없이 곧바로** 뜨고
(서버가 RTDB `/talentSeen` 을 구독해 관리자 소켓으로 `talent:seen` 을 보낸다 —
`yvServer/talent/talentFeed.js`), 방금 댄 카드는 몇 초 동안 '방금 태깅' 으로 물든다.
거기서 셋 중 하나로 정한다:

- **신규 등록** — 새 키링을 받은 어린이
- **기존 사용자 매칭** — 키링을 잃어버려 다시 받은 경우(이름·잔액을 옮긴다)
- **포인트 카드** — 어린이가 아니라 지급/사용 카드

### 출석모드

`attendanceMode` 를 켜면 카드 단계를 건너뛴다. **키링 한 번 + 확인 한 번**으로 바로
지급된다. 주일 아침처럼 줄이 길고 사유가 하나로 정해진 자리를 위한 것이다.
무엇으로 지급할지는 `attendanceCard`(카드 UID)로 정하고, 비워 두면 그 기기에서 쓸 수
있는 첫 카드를 쓴다.

### 테두리가 방향을 말한다

`+` / `-` 부호는 쓰지 않는다. 대신 **화면 테두리 4px** 이 지금 태깅하면 무슨 일이
일어나는지 알린다:

| 테두리 | 탭 | 태깅하면 |
|--------|-----|----------|
| 초록 | 지급 | 포인트가 오른다 |
| 빨강 | 사용 | 포인트가 내린다 |
| 회색 | 내역 | 잔액은 건드리지 않고 조회만 한다 |

획 하나(`+`/`-`)는 멀리서 안 보이지만 테두리 색은 보인다. 잘못된 방향으로 태깅해
잔액이 반대로 움직이는 사고를 막는 것이 목적이라, 화면 어디를 보고 있든 눈에
들어오는 신호를 골랐다.

`modeLock` 이 걸린 기기(지급 전용/사용 전용)는 그 탭과 내역 **두 칸만** 뜬다.
누를 수 없는 칸을 띄워 두면 고장으로 보인다.

### 탭 버튼과 터치 영역

탭 그림은 원본 한 장(`tools/artwork-src/tabs.png`)에 지급·사용이 나란히 들어 있고,
두 알약 **사이 틈에서 갈라** 각자 바깥 배경까지 가져간다. 붙여 놓으면 원본의 한 덩어리
모양이 그대로 복원되므로 버튼 사이 틈은 **0** 이다.

배경까지 넣어 자르는 이유는 **누를 수 있는 자리를 넓히기 위해서**다. 기기의 `tabHit` 은
그림 사각형을 그대로 쓰므로, 알약만 잘라 두면 가장자리를 눌렀을 때 안 먹는다.

**탭 그림은 펌웨어에 없다.** 서버가 늘 내려준다 — 관리자가 올린 것이 없으면 서버가
들고 있는 기본 그림(`yvServer/talent/default-art/`)을 대신 준다. 그림을 바꿀 때마다
기기를 다시 굽지 않아도 되게 하려는 것이고, 덕분에 펌웨어가 58KB 줄었다.

관리자 화면(리더설정 → 탭 버튼)에서 네 장을 올리면 그것이 기본값을 이긴다. 한 쪽은
**고른 상태와 아닌 상태가 둘 다** 있어야 쓰인다 — 하나만 있으면 고를 때마다 크기가
달라져 배치가 흔들리므로, 서버가 그 규칙으로 걸러 보낸다(짝이 안 맞으면 그 쪽은 기본값).

아직 그림을 못 받은 상태(첫 부팅, 통신 실패)에서는 **색 칠한 칸에 "지급"·"사용" 글자**로
대신한다. 빈 줄을 두면 고장으로 보이기 때문이다.

| | 예전 | 지금 |
|---|---|---|
| 그림 | 97×44 · 85×44 | **105×72 · 96×72** |
| 탭 줄 높이 | 52 | **78** |
| 누르는 자리 | 알약 모양만 | **그림 사각형 전체(배경 포함)** |

탭 줄이 커진 만큼 **내용 영역이 218 → 192px** 로 줄었다. 서버의 그림 규격도 함께
맞춰야 한다(`talentArt.js`) — 기기는 배경의 폭·높이가 정확히 같을 때만 쓰므로,
어긋나면 조용히 흰 바탕으로 떨어진다.

| 그림 | 규격 |
|---|---|
| 배경(`bg`) | 232×**192** (예전 232×218 — **다시 올려야 한다**) |
| 포인트(`point`) | 폭 108 · 높이 ≤ **132** |
| 메뉴 항목(`menu`) | 폭 108 · 높이 ≤ **110** |
| 카드(`card`) | 폭 108 · 높이 ≤ 132 |
| 완료(`done`) | 폭 200 · 높이 ≤ **100** |
| 탭 버튼(`tab`) | 높이 **72** · 폭 ≤ 116 · `earn`·`earn-off`·`spend`·`spend-off` 네 장 (안 올리면 서버 기본값) |
| 헤더 띠(`header`) | **232×42** · `on`(연결됨)·`off`(끊김) 두 장 |
| 켤 때 뜨는 화면(`splash`) | **240×320** · 화면 전체 한 장 |

### 바탕색은 탭마다 다르다

| 탭 | 내용 영역 바탕 | 이유 |
|----|----------------|------|
| 지급 · 사용 · 내역 | **설정색** (`bgColor`, 기본 `#EBAC42`) | 관리자 화면에서 고른다. 헤더·탭 줄의 빈자리도 같은 색이라 위에서 아래까지 한 장으로 이어진다 |
| 배경 사진을 올린 기기 | 사진 | 지급·사용에만 깐다. 사진 위에는 늘 흰 글자다 |

목록의 줄무늬와 페이지 띠는 **바탕색에서 한 단계 눌러** 만든다(`bgShade`). 밝은 바탕이면
어둡게, 어두운 바탕이면 밝게 — 어떤 색을 넣어도 뒤집히지 않는다.

**내역은 탭 줄 없이 전체 화면을 쓴다.** 목록은 한 줄이라도 더 들어가는 편이 낫고,
거기서는 지급·사용을 고를 일이 없어 버튼이 자리만 차지한다. 나올 때는 헤더 띠를
다시 누른다.

글자색은 자리마다 정하지 않고 **역할**로 부른다 — `inkMain()` / `inkSub()` /
`inkMuted()` / `inkDir(up)`. 같은 자리라도 바탕이 밝으냐 어두우냐에 따라 읽히는
색이 반대라, 그리는 쪽에서 매번 고르면 한 군데씩 빠뜨리게 된다.

**어둡게 쓸지 밝게 쓸지는 바탕색의 밝기가 정한다.** BT.601 가중 밝기
(`r*299 + g*587 + b*114`)가 140 이상이면 어두운 글자를 쓴다 — 사람 눈은 초록에
민감하고 파랑에 둔해서 단순 평균으로는 갈리지 않는다. 관리자가 어떤 색을 넣어도
글자가 읽히게 하려는 것이다.

흰 바탕에서는 방향색도 한 단계 진한 쪽을 쓴다(`C_EARN_D`·`C_SPEND_D`) — 밝은
초록은 흰 종이 위에서 눈에 잡히지 않는다.

**그림은 흰색에 합성해 둔다.** RGB565 에는 투명도가 없어서 서버(`talentArt.js`)와
`tools/make-artwork.py` 가 알파를 미리 배경색에 합성한다. 검정에 합성한 그림을 흰
바탕에 올리면 검은 네모가 남는다. → 이미 올려 둔 포인트·메뉴 그림은 **한 번 다시
올려야** 흰 바탕에 맞는다(배경 사진은 그대로 두면 된다 — 어두운 막이 씌워져 있고
그 위는 계속 흰 글자다).

### 항목별 포인트 (메뉴)

지급·사용 탭은 화면 **오른쪽 108px** 에 항목 목록을 띄운다. 눌러서 고른 항목의
포인트로 처리하고, 항목 이름은 서버의 `reason` 으로 보내 내역에도 남긴다 —
잔액 변화만으로는 "무엇을 샀는지" 를 알 수 없기 때문이다.

목록은 서버 설정 `earnMenu` · `spendMenu` 에서 온다. 제약이 전부 화면에서 나온다:

| 제약 | 값 | 왜 |
|------|-----|-----|
| 이름 길이 | 5자 | 14px 한글 5자 = 70px, 여백 12 + 세 자리 금액 24 = 106 ≤ 108 |
| 금액 | 1~999 | 네 자리면 이름과 붙는다 |
| 항목 수 | 8개 | 28px 줄로 232px 안에 여덟 개 |

**이 메뉴는 이제 대비책이다.** "무엇을 얼마나" 는 지급/사용 카드가 말한다(위 참고).
카드가 한 장도 등록되지 않았거나 옛 서버에 붙은 기기에서만 이 목록이 쓰인다 —
카드를 잃어버린 날에도 리더가 멈추지 않게 하려는 것이라 지우지 말 것.
메뉴까지 비우면 `talentStep` 하나를 가운데에 크게 띄운다.

고른 항목은 탭마다 따로 기억한다(`selEarn`/`selSpend`). 지급에서 '전도' 를 골라 뒀는데
사용 탭에 다녀오면 풀리는 것은 현장에서 짜증나는 동작이다.

### 이름 표시

부팅할 때 `GET /api/talent/roster` 로 UID→이름 목록을 받아 둔다. 태그를 대는 순간
이름을 띄우려면 서버 왕복(1초 가까이)을 기다릴 수 없기 때문이다. 이름이 없는
키링은 UID 를 그대로 보여준다.

### 내역 탭

`GET /api/talent/feed?limit=<화면에 들어가는 줄 수>&page=<쪽>` 을 열 때마다 받는다
(30초 안에 다시 열면 그대로 쓴다). 서버는 **기록된 시각(`at`) 기준 최신순**으로 주고,
`page` 0 이 가장 최근 묶음이다. 열 때는 늘 0쪽부터 — 지난번에 넘겨 둔 쪽에서
시작하면 방금 찍힌 것이 안 보여 "안 들어갔다"로 읽힌다.

내용 영역 위·아래에 페이지 띠를 하나씩 둔다. 위는 더 최근(이전 페이지), 아래는 더
예전(다음 페이지)이다. `limit` 을 화면에 들어가는 줄 수와 같게 맞춰 두어, 넘길 때
몇 건이 소리 없이 건너뛰어지는 일이 없다. 다음 쪽이 남았는지는 서버가 `hasMore` 로
알려 준다 — 끝에 닿으면 띠가 회색이 되고 눌러도 아무 일도 하지 않는다.

"3분 전" 은 서버가 준 `agoSec` 에 기기가 깨어 있던 시간을 더해 센다 — 리더에는
RTC 도 NTP 도 없다.

**내역 탭에서 키링을 대면** 지급도 사용도 하지 않고 그 키링의 잔액과 최근 4건을
보여준다(`GET /api/talent/feed?uid=...`, 5초). 잔액과 내역을 한 번에 받는 이유는
두 번 왕복하면 대고 나서 화면이 뜰 때까지가 눈에 띄게 늘어지기 때문이다.
등록되지 않은 키링이면 잔액 0 을 크게 띄우는 대신 "아직 등록되지 않은 키링입니다"
라고 말한다 — 0포인트인 사람으로 읽히지 않게.

깨어날 때 WiFi 에 붙는다(최대 8초 대기). 접속 실패해도 화면은 뜨고, 태깅할 때
"처리하지 못했습니다 / 네트워크 없음" 으로 알린다.

## 배선

전원은 TFT·PN532·부저 모두 3.3V, 공통 GND.

**핀 번호는 두 곳에서 온다.** 화면·터치의 SPI 핀은 `build.sh` 의 빌드 플래그가 정하고
(TFT_eSPI 가 그 값을 받는다), 나머지는 `.ino` 의 `PIN_*` 이 정한다. 고칠 때는 그 두
곳만 보면 된다 — 이 표는 사본이다.

| 기능 | GPIO | 정하는 곳 |
|------|------|-----------|
| TFT CS / DC / RST | **8 / 17 / 18** | `build.sh` |
| TFT MOSI / SCK / MISO | **16 / 15 / 6** | `build.sh` |
| TFT 백라이트 (PWM) | **7** | `.ino` `PIN_TFT_BL` |
| **터치 T_CS (XPT2046)** | **5** | `build.sh` `-DTOUCH_CS` |
| **터치 T_IRQ** | **4** (딥슬립 기상용, `sleepEnabled` 일 때만 필요) | `.ino` `PIN_TOUCH_IRQ` |
| PN532 SDA / SCL | **9 / 10** | `.ino` `PIN_NFC_SDA/SCL` |
| 부저 | **11** | `.ino` `PIN_BUZZER` |

### 왜 이런 번호인가

번호만 보면 뒤죽박죽이지만, **보드 왼쪽 헤더에 꽂는 자리는 TFT 14핀 헤더의 신호
순서와 그대로 맞는다.** 손배선에서 중요한 것은 번호가 아니라 구멍의 순서다 —
옆으로 나란히 가면 선이 안 꼬인다.

```
보드 왼쪽 헤더(위→아래)        TFT 14핀 헤더(위→아래)
 4번째  GPIO4  ────────────   1  T_IRQ
 5번째  GPIO5  ────────────   4  T_CS
                              2  T_DO  ┐ 모듈 쪽에서 짧게 물린다
                              3  T_DIN ┤ (기판 안에서 이어져 있지 않다)
                              5  T_CLK ┘
 6번째  GPIO6  ────────────   6  SDO(MISO)
 7번째  GPIO7  ────────────   7  LED
 8번째  GPIO15 ────────────   8  SCK
 9번째  GPIO16 ────────────   9  SDI(MOSI)
10번째  GPIO17 ────────────  10  DC
11번째  GPIO18 ────────────  11  RESET
12번째  GPIO8  ────────────  12  CS
                             13  GND → 헤더 맨 아래 GND
                             14  VCC → 헤더 맨 위 3V3
```

13·14번째 구멍(GPIO3·GPIO46)은 스트래핑 핀이라 건너뛰고, 그 아래 15~17번째를
PN532(9·10)와 부저(11)에 준다. 피한 핀: 0·3·45·46(스트래핑), 19·20(USB),
43·44(UART0).

터치 패널은 화면과 **같은 SPI 버스**를 쓰고 CS 만 따로 받는다. TFT_eSPI 가 XPT2046 을
직접 다루므로 별도 라이브러리가 필요 없고, `build.sh` 의 `-DTOUCH_CS=5` 하나로 켜진다.

`T_IRQ` 는 평소에는 쓰지 않는다(폴링). 딥슬립을 켠 기기만 화면 터치로 깨어나야 해서
RTC 핀인 GPIO4 에 물리고 `esp_sleep_enable_ext0_wakeup()` 으로 받는다.
**GPIO4 정전식 패드는 더 쓰지 않는다** — 터치 임계값 실측(`CALIBRATE_TOUCH`)도 함께 없앴다.

터치 좌표 보정값은 `.ino` 의 `TOUCH_CAL` 에 있다. 패널마다 달라 새 모듈로 바꾸면
TFT_eSPI 의 `Touch_calibrate` 예제로 다시 뽑아야 한다 — 그대로 두면 탭이 눌리는
자리가 어긋난다.

PN532 의 **IRQ·RESET 은 연결하지 않는다.** 스케치에서 `Adafruit_PN532(-1, -1, &Wire)`
로 만들어 I2C RDY 바이트로 준비 여부를 확인한다. 모듈의 모드 스위치는 **I2C** 로 둘 것.

## 빌드

```bash
./build.sh              # 컴파일
./build.sh --upload     # 컴파일 + 업로드
./build.sh --upload /dev/cu.usbmodem2101   # 포트 지정
```

`arduino-cli compile` 을 그냥 쓰면 안 된다. TFT_eSPI 는 설정을 라이브러리 폴더
(`User_Setup_Select.h`)에서 읽는데, 이 PC 에는 TTGO T-Display 용 Setup25 가 활성화돼
있어 그대로 쓰면 서로 덮어쓴다. `build.sh` 는 라이브러리를 건드리지 않고
`-DUSER_SETUP_LOADED` 와 핀 정의를 **이 스케치에만** 주입한다.

필요 라이브러리:

```bash
arduino-cli lib install "TFT_eSPI" "Adafruit PN532"
```

## 한글 표시

TFT_eSPI 내장 폰트는 ASCII 전용이라 한글이 깨진다. `FontKR14.h` 를 스무스폰트(VLW)로
구워 넣었다 — **14px, ASCII 95자 + KS X 1001 상용 2350자** (2,445 글리프 / 473KB).

**VLW 는 구워 넣은 크기로만 그려진다.** `setTextSize()` 가 먹지 않아 크기마다 한 벌씩
든다 — `FontKR14.h`(473KB)와 `FontKR20.h`(916KB) 둘이다.

| 크기 | 쓰는 곳 |
|------|---------|
| 20px | 화면 제목 · 탭 · 이름 · "키링을 대주세요" · 오류 첫 줄 — 멀리서 읽혀야 하는 줄 |
| 14px | 내역 목록 · 부가 문구 — 전부 키우면 내역 여덟 줄이 안 들어간다 |
| 내장 6번(48px) · 4번(26px) | 잔액·포인트 숫자 (숫자뿐이라 내장 폰트로 충분) |

전환은 `useFont(px)` 하나로 한다. `loadFont()` 가 글리프 메트릭 2,445개를 힙에
올리므로(약 20KB), **같은 폰트를 다시 올리지 않게 막아 두었다** — 없으면 화면 한 장
그리는 동안 열 번 넘게 재할당된다. 숫자를 내장 폰트로 그릴 때는 `useFont(0)` 로 내려야 한다.

두 벌을 들고도 3MB 파티션의 **81%**, RAM 17% 다.

예전에는 화면에 쓰는 낱말 129자만 담았는데, 서버(`deviceLabel`)가 문구를 정하게 되면서
그 방식으로는 부족해졌다. 지금은 관리자가 무엇을 입력하든 대체로 그려진다.

```bash
./../tools/make-fonts.sh          # FontKR14.h · FontKR20.h 재생성 (커밋하지 않는 생성물)
```

한글 음절 전체(11,172자)는 14px 에서 2.4MB 라 Huge APP(3MB)에 앱과 함께 들어가지 않아
상용 2350자로 맞췄다. 그 밖의 글자는 서버가 저장 단계에서 막는다.

증감 숫자는 크게 보여야 해서 내장 폰트(6번)를 쓰는데, 스무스폰트가 올라가 있으면
폰트 번호가 무시되므로 그 구간만 `krFont(false)` 로 잠깐 내렸다가 올린다.

## 터치 임계값 보정 (처음 한 번 필요)

보드·패드마다 값이 다르다. 스케치 상단의 `CALIBRATE_TOUCH` 를 1 로 바꿔 굽고,
시리얼에 찍히는 값을 손 뗐을 때와 댔을 때 각각 확인한 뒤 중간값을 `TOUCH_THRESH` 에 넣는다.

```cpp
#define CALIBRATE_TOUCH 1
```

ESP32-S3 는 **터치하면 값이 커진다**(구형 ESP32 와 반대). 깨우기도 "임계값 이상"으로 건다.

## 소리

부저는 GPIO 와 GND 사이에 그냥 물려 있다 — 트랜지스터도 증폭단도 없다. 그래서
소리 크기를 키울 손잡이는 **주파수** 하나뿐이다. 얇은 피에조 판은 자기 공진점
언저리(12~14mm 판이면 대략 2.3~3.0kHz)에서만 제대로 울고, 거기서 멀어지면 같은
전압을 줘도 소리가 급격히 작아진다. 예전 값(300~2000Hz)은 대부분 그 아래여서
"울리지 않고 딸깍대는" 소리가 났다 — 특히 실패음 300Hz 는 행사장에서 사실상
들리지 않았다. 그래서 전부 2.0~3.2kHz 안으로 옮겼다.

뜻을 나누는 것은 세기가 아니라 **방향과 개수**라, 대역을 옮겨도 "오르면 지급,
내리면 사용" 은 그대로다.

| 이벤트 | 패턴 |
|--------|------|
| 전원 ON | 2093 → 2637 → 3136Hz (상승 3연음) |
| 전원 OFF | 3136 → 2637 → 2093Hz (하강 3연음) |
| 지급 | 2637 → 3136Hz (짧게 위로) |
| 사용 | 3136 → 2093Hz (짧게 아래로) |
| 실패 | 1976Hz 두 번 (대역 안에서 가장 낮은 쪽) |
| 탭 전환 | 2637Hz 짧게 |

음 사이에 18ms 무음을 둔다(`BUZ_GAP`). 붙여서 내면 두 음이 한 음처럼 뭉개져
지급(2연음)과 탭 전환(1음)이 구별되지 않는다. `noTone()` 뒤에 핀을 LOW 로 내리는
것도 같은 이유다 — HIGH 로 남으면 판이 눌린 채 있어 다음 음이 둔해진다.

`beep()` 이 재생 시간만큼 붙잡아 두므로 딥슬립 직전 전원 OFF 음도 잘리지 않는다.

## 달란트 저장 — 서버 DB

잔액은 **yvServer(youthvision.co.kr)의 MongoDB** 가 단일 출처다.
같은 API 가 jdServer(jesusdream.kr)에도 올라가 있어, 접속 서버를 바꾸려면
`ChurchSecrets.h` 의 `TALENT_API_BASE` 한 줄만 고치면 된다(기기 키는 두 서버가 같다). 리더는 저장하지 않고
매번 서버에 묻는다. 리더를 여러 대 놓아도 잔액이 하나로 모이고, 지급·사용 내역이
서버에 남아 "왜 이 잔액인지" 설명할 수 있다.

| 메서드 | 경로 | 용도 |
|--------|------|------|
| POST | `/api/talent/earn` | 지급 (기기 키 필요) — `card` UID 를 보내면 금액은 서버가 찾는다 |
| POST | `/api/talent/spend` | 사용 (잔액 부족 시 409) |
| GET | `/api/talent/cards` | 지급/사용 카드 목록 (기기 키 또는 관리자) |
| PUT/DELETE | `/api/talent/cards/:uid` | 카드 등록·수정·삭제 (관리자) |
| POST | `/api/talent/seen` | 처음 보는 UID 알림 (기기 키) |
| GET/DELETE | `/api/talent/seen` | 미등록 카드 목록·치우기 (관리자) |
| GET | `/api/talent/:uid` | 잔액 조회 (공개) |
| GET | `/api/talent` | 전체 목록 (관리자) |
| GET | `/api/talent/logs?uid=&limit=` | 증감 내역 (관리자) |

요청/응답:

```
POST /api/talent/earn
  헤더 : x-talent-key: <TALENT_DEVICE_KEY>
  본문 : { "uid": "04AABBCCDD", "card": "04C1D2E3", "device": "nfc-reader-1" }
  응답 : { "success": true, "uid": "...", "balance": 7, "delta": 5, "item": "출석" }

  card 대신 amount 를 보내는 예전 방식도 계속 받는다(메뉴를 쓰는 기기).
  card 를 주면 금액·이름·분류는 서버가 그 카드에서 찾는다.
```

**기기 키**: 달란트는 포인트라 인증 없이 열면 누구나 지급할 수 있다. 그래서 쓰기는
`x-talent-key` 헤더를 서버의 `TALENT_DEVICE_KEY`(.env)와 대조한다. 기기 쪽 값은
`~/Documents/Arduino/libraries/ChurchSecrets/ChurchSecrets.h` 에 있다. 두 값이 같아야 한다.

**네트워크가 끊기면 처리하지 않는다.** 화면에 사유를 띄우고 실패음을 낸다.
잔액은 건드리지 않으므로 나중에 다시 태깅하면 된다. (오프라인 대기열은 넣지 않았다)

## 서버에서 내려받는 설정

부팅할 때 `GET /api/talent/config?device=<TALENT_DEVICE_ID>` (헤더 `x-talent-key`) 로 설정을 받아
NVS(`talentcfg`)에 캐시한다. 화면은 **캐시로 먼저 그리고** 설정 갱신은 그 뒤에 하므로,
서버가 느리거나 꺼져 있어도 깨어나는 속도는 그대로다. 서버에 못 붙으면 캐시 → 기본값 순으로 물러선다.

| 키 | 기본값 | 범위 | 하는 일 |
|---|---|---|---|
| `talentStep` | 1 | 1~1000 | 카드도 메뉴도 없을 때 쓰는 값 |
| `attendanceMode` | false | | 켜면 카드 단계를 건너뛴다(키링 한 번으로 지급) |
| `attendanceCard` | '' | 20자 | 출석모드에서 쓸 카드 UID (비우면 첫 카드) |
| `doneMs` | 3000 | 1000~15000 | 완료 그림을 띄워 두는 시간 |
| `defaultMode` | `earn` | earn/spend | 부팅 직후 모드 |
| `modeLock` | `both` | both/earn/spend | 잠그면 터치로 모드를 못 바꾼다 |
| `sleepTimeoutMs` | 15000 | 5000~600000 | 무입력 후 딥슬립까지 |
| `tagCooldownMs` | 1500 | 200~10000 | 같은 키링 연속 처리 방지 |
| `touchDebounceMs` | 400 | 100~3000 | 터치 연속 인식 방지 |
| `httpTimeoutMs` | 6000 | 1000~20000 | 서버 요청 상한 |
| `rotation` | 0 | 0~3 | 거치 방향 (**다음 부팅에 적용**) |
| `backlight` | 255 | 10~255 | 백라이트 밝기 |
| `sound` | true | | 부저 on/off |
| `bgColor` | `#EBAC42` | `#RRGGBB` | 내용 영역 바탕색 (배경 그림이 있으면 그림이 이긴다) |
| `deviceLabel` | 달란트 | 10자 | 화면 왼쪽 위 제목 |
| `configTtlSec` | 300 | 30~86400 | 깨어 있는 동안 재조회 주기 |

깨어 있는 동안에는 `configTtlSec` 마다 다시 받는다. 행사 중에 관리자가 값을 바꾸면
기기를 만지지 않아도 반영된다(`rotation` 만 예외 — 화면을 다시 그려야 해서 다음 부팅에 적용).

### 서버에서 못 바꾸는 값

- **`TOUCH_THRESH`** — 딥슬립 기상 조건이라 잘못된 값을 받으면 터치로 못 깨어나고
  설정을 다시 받으러 갈 수도 없다. 전원을 뽑아야만 복구되므로 펌웨어에 고정한다.
- **WiFi/서버 주소/기기 키** (`ChurchSecrets.h`) — 이걸로 서버에 접속하므로 서버에서 받을 수 없다.
- **핀 정의** — 하드웨어 고정값.

### 화면 문구에 쓸 수 있는 글자

`FontKR14.h` 에는 **ASCII 95자 + KS X 1001 상용 2350자**가 14px 로 구워져 있다(총 2,445 글리프, 473KB).
실제 한국어 문서에 쓰이는 음절은 사실상 이 안에 다 들어오므로, `deviceLabel` 은 자유롭게 정해도 된다.

한글 음절 전체(11,172자)를 담으면 14px 에서 **2.4MB** 라 Huge APP(3MB)에 앱과 함께 들어가지 않는다.
그래서 상용 2350자로 맞췄다. 그 밖의 글자(예: 뷁)를 넣으면 서버가 저장 단계에서 막고 알려준다.

폰트를 다시 만들려면:

```bash
./tools/make-fonts.sh
```

글자 집합을 바꿀 때는 `yvServer/talent/talentConfig.js` 의 `FONT_HANGUL` 규칙도 함께 맞춰야 한다
(지금은 양쪽 다 "EUC-KR 로 인코딩되는 한글" 이라는 같은 규칙으로 만들어 쓴다).

## 아직 확인하지 못한 것

실물 보드가 없어 **컴파일과 폰트 검증까지만** 했다. 다음은 기기에서 봐야 한다.

- 터치 임계값 (위 보정 절차 필요)
- PN532 인식 — 못 찾으면 화면에 "NFC 모듈 없음" 이 뜬다
- 딥슬립 복귀 후 TFT 재초기화
- 화면 레이아웃 (240x320 세로 기준으로 좌표를 잡았다)
- WiFi 접속 시간 — 깨어날 때마다 붙으므로 체감 지연이 얼마나 되는지
