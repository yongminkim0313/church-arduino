# TalentNfcReader_JC3245 — 가이션 JC3248W535 판 NFC 키링 리더

[`../TalentNfcReader`](../TalentNfcReader/README.md) 를 **화면·터치가 한 판에 붙어 나오는
기성품 보드**로 옮긴 것이다. 하는 일과 화면 흐름은 원본과 같으므로, 동작 설명은
[원본 README](../TalentNfcReader/README.md) 를 본다. 이 문서는 **다른 점만** 적는다.

| | 원본 TalentNfcReader | 이 폴더 |
|---|---|---|
| 보드 | ESP32-S3-DevKitC-1 + 손배선 | JC3248W535C_I_Y (ESP32-S3-WROOM-1 N16R8) |
| 화면 | 2.8" 240×320 ILI9341 (SPI) | 3.5" 320×480 IPS AXS15231B (QSPI, 붙박이) |
| 터치 | XPT2046 저항막 (보정 필요) | 정전식 — 화면과 같은 칩을 I2C 로 (보정 없음) |
| 그리는 라이브러리 | TFT_eSPI | Arduino_GFX + 이 폴더의 껍데기 |
| 손으로 잇는 것 | 화면 14선 + PN532 + 부저 | **PN532 넉 선뿐** |
| 화면 회전 | 0·1·2·3 | 0(세로)만 |
| 소리 | 피에조 부저 | 기본 없음 |

## 배선

화면·터치·백라이트는 보드 안에 붙박이라 **손댈 것이 없다.** 바깥으로 나온 1.25mm JST
커넥터의 네 선에 PN532 모듈만 잇는다.

```
  보드 JST 커넥터        PN532 (I2C 모드)
    3V3    ───────────   VCC
    GND    ───────────   GND
    GPIO17 ───────────   SDA
    GPIO18 ───────────   SCL
```

PN532 모듈의 작은 스위치는 **I2C 자리**에 둔다(보통 1:OFF, 2:ON).

화면 터치도 I2C(GPIO4·8)지만 그쪽은 보드 안에서 이미 물려 있다. PN532 는 **두 번째
버스(`Wire1`)** 로 따로 연다 — 한 버스에 묶으면 터치를 읽을 때마다 PN532 의 응답을
기다리게 되어 화면이 굼떠진다.

### 보드가 쓰고 있는 핀 (건드리지 말 것)

| 핀 | 쓰임 |
|----|------|
| 45 · 47 · 21 · 48 · 40 · 39 | 화면 QSPI (CS · SCK · D0~D3) |
| 1 | 백라이트 (PWM) |
| 4 · 8 | 터치 I2C (SDA · SCL, 주소 0x3B) |
| 3 | 터치 INT — 딥슬립에서 화면을 눌러 깨울 때 쓴다 |

## 빌드

```bash
./TalentNfcReader_JC3245/build.sh            # 컴파일
./TalentNfcReader_JC3245/build.sh --upload   # 컴파일 + 업로드
```

**PSRAM(opi)을 반드시 켜야 한다** — 화면 버퍼 300KB 를 거기에 잡는다. build.sh 의 FQBN 에
들어 있다. 파티션은 원본과 같은 표(앱 4MB + LittleFS 11.875MB)를 쓴다.

필요 라이브러리:

```bash
arduino-cli lib install "GFX Library for Arduino" "Adafruit PN532" "ArduinoJson" "NimBLE-Arduino"
```

폰트 헤더는 저장소에 없다(파생 파일). 클론 직후 한 번 만든다:

```bash
./tools/make-fonts.sh
```

현재 크기: 플래시 3,690,266B(3.69MB) / 앱 칸 4MB · 전역 108,856B. 한글 폰트 두 벌(20·24px)이 2.1MB 라
**앱 칸에 여유가 500KB 남짓**이다. 더 큰 글자가 필요하면 파티션표부터 손볼 것.

## 화면을 어떻게 그리는가

이 보드의 패널은 QSPI 다. **TFT_eSPI 는 QSPI 를 다루지 못한다** — 그래서 그리는 일은
Arduino_GFX 가 맡는다. 그런데 본체(`.ino`)는 3,800줄 내내 `tft.drawString`·`tft.fillRect`·
`tft.getTouch` 를 부른다. 그 호출을 전부 고치는 대신 **같은 이름의 껍데기**를 두어
본체를 거의 그대로 옮겼다. 화면이 또 다른 보드로 옮겨 가도 이 두 파일만 갈면 된다.

| 파일 | 하는 일 |
|------|---------|
| `PanelTFT.h/.cpp` | `tft.*` 를 Arduino_GFX 로 옮겨 준다. 터치(I2C)도 여기서 읽는다 |
| `VlwFont.h/.cpp` | 한글 스무스폰트(VLW)를 직접 읽어 글자를 그린다 |

### 통짜 버퍼로 그린다

AXS15231B 는 **일부 물량에서 '창 주소(부분 갱신)' 명령을 무시한다**고 알려져 있다.
그래서 320×480 버퍼(PSRAM 300KB)에 다 그린 뒤 통째로 민다. 미는 일은 33ms 마다 도는
전용 태스크가 코어 0 에서 맡는다.

- 그리는 쪽(본체)은 버퍼에만 쓰므로 QSPI 버스를 다투지 않는다.
- 본체 곳곳에 `flush()` 를 흩뿌리지 않아도 된다 — 원본 코드를 그대로 두는 값이다.
- 그리는 도중에 밀리면 그 프레임만 반쯤 나가지만 33ms 뒤 메워진다.

### 한글 폰트

VLW 는 TFT_eSPI 의 스무스폰트 형식이다. Arduino_GFX 에는 이것을 읽는 기능이 없어
`VlwFont` 가 직접 읽는다(머리 24B → 글리프 28B × N → 8비트 알파 비트맵). 글자를 놓는
자리와 폭 계산은 TFT_eSPI 와 같게 맞췄다 — 안 그러면 본체가 잡아 둔 좌표가 어긋난다.

덤으로 **글리프 찾기가 이분 탐색**이다(TFT_eSPI 는 선형 탐색이라 2,350자에서 느려진다).
알파는 버퍼에 이미 있는 점과 섞으므로, 사진 위에 쓴 글자도 테두리가 곱게 나온다.

폰트 해석이 맞는지는 보드 없이 한 번 맞춰 봤다 — 같은 규칙을 파이썬으로 옮겨
글리프를 그려 보고, 메트릭으로 계산한 파일 크기가 실제 파일 크기와 맞는지,
`textWidth` 가 실제로 그린 폭과 같은지 확인했다(둘 다 맞았다). 그때 문구에 쓰는
가운뎃점(·)이 폰트에 없다는 것도 드러나서, 두 한글 폰트에 따로 넣어 구웠다.

| 폰트 | 어디에 |
|------|--------|
| `FontKR20` (2,350자) | 본문·목록 — 본체의 `useFont(14)` |
| `FontKR24` (2,350자) | 이름·안내문 — 본체의 `useFont(20)` |
| `FontNum34` | 잔액 숫자 — 원본의 내장 폰트 4번 자리 |
| `FontNum64` | 완료 화면의 큰 숫자 — 원본의 내장 폰트 6번 자리 |

화면이 커진 만큼(240×320 → 320×480) 한 단계씩 키워 두었다. 원본과 같은 크기로 돌리려면
`useFont()` 의 두 줄에서 폰트만 바꿔 끼우면 된다. 폰트는 네 벌까지 올려 둔 채로 쓴다 —
칸을 두지 않으면 화면 한 장에 2,350자 메트릭을 여러 번 훑게 된다.

## 실기에서 확인한 것

2026-09-16 JC3248W535C_I_Y 에 구워 봤다(3,690,266B · 전역 108,856B).

- 화면·한글 글자·색(바탕 주황) 정상
- 와이파이 연결 → 서버 설정 받기 정상
- 터치 — 헤더 띠로 내역 열기. 처음에는 **한 번 누름이 두 번 누름으로** 세어졌다(아래)

### 겪은 문제

**1. 한 번 눌러도 두 번 누른 것이 된다.** AXS15231B 는 새 좌표가 없는 틈에 0 이 아니라
**헛값**(손가락 수가 1 보다 큼)을 준다. 손가락을 대고 있는 동안에도 11~22ms 마다
'유효 좌표 ↔ 헛값' 이 번갈아 왔다. 헛값을 '뗌' 으로 읽으면 한 번 누르는 사이에 누름이
수십 번 들어가, 첫 누름 120ms 뒤의 되누름이 두 번째 탭으로 세어졌다.
→ 헛값은 '새 소식 없음' 으로 보고, 마지막 유효 좌표 뒤 `TOUCH_HOLD_MS`(60ms) 동안은
누른 채로 친다(`PanelTFT::getTouch`).

**2. 내장 LED 코드가 GPIO48 을 흔든다.** 코어의 esp32s3 변형이 `RGB_BUILTIN` 을 GPIO48 로
두는데, 이 보드에서 48번은 **화면 QSPI 데이터선(D1)** 이다. 원본의 상태 LED 코드를 그대로
두면 화면을 깨뜨린다. 이 스케치에서는 LED 를 자동으로 잡지 않게 막았다
(형제 보드 T-RGB 에서는 같은 자리가 I2C SCL 이라 터치가 통째로 죽었다).

**3. C to C 케이블로는 맥에 안 잡힌다.** 보드의 Type-C 에 CC 저항이 없어 **A to C 케이블**
이라야 한다(설명서에도 있다).

**4. 미는 일과 패널 명령이 같은 QSPI 버스를 다툰다.** 이 스케치에서 터진 것은 아니고,
같은 껍데기를 쓰는 형제 스케치 `GodlifeScheduleNext_JC3248` 을 실기에 구웠을 때
켜자마자 부팅 루프로 드러났다(그쪽은 첫 화면을 바로 보이려고 `setup()` 에서 `flushNow()` 를 부른다).

```
E spi_master: Cannot send polling transaction while the previous ... not terminated
assert failed: spi_device_polling_end spi_master.c:1476 (host->cur_cs == handle->id)
```

미는 일은 코어 0 의 태스크가, 패널 명령은 본체(코어 1)가 부른다 — 겹치면 ESP-IDF 가
그 자리에서 죽는다. 여기서는 `flushNow()` 를 쓰지 않아 아직 안 터졌을 뿐, 화면을 재우는
`writecommand(0x10)` 이 같은 자리에 있어 **딥슬립을 켠 기기에서 언제든** 같은 일이 난다.
→ `PanelTFT.cpp` 에 버스 자물쇠(뮤텍스)를 두고 `flush()` 와 `writecommand()` 를 묶었다.
그리는 일(버퍼에 쓰기)은 메모리뿐이라 자물쇠 밖이다.
(RGB 패널을 쓰는 `TalentNfcReader_CST820` 판은 미는 태스크가 없어 이 자물쇠가 필요 없다.)

### 아직 확인하지 못한 것

1. **PN532** — 아직 붙여 보지 않았다. 시리얼에 펌웨어 판 번호가 찍히는지 볼 것.
   안 찍히면 스위치(I2C)와 넉 선(GPIO17·18)을 본다.
2. **헤더 띠 두 번 누르기** — 사진 모두 받기가 뜨는지(터치 수정 뒤 한 번 누르기만 확인).
3. **밀리는 속도** — 통짜 300KB 를 33ms 마다 민다. 느리게 느껴지면 태스크 주기를 늘린다.
4. **딥슬립 기상** — `sleepEnabled` 를 켠 기기에서 화면을 눌러 깨어나는지(GPIO3).

## 소리

이 보드에서 바깥으로 나온 핀이 둘뿐이라 PN532 에 다 썼다. 그래서 부저는 달지 않았고
`PIN_BUZZER` 가 `-1` 이라 `beep()` 는 아무 일도 하지 않는다. 보드의 스피커 커넥터로
소리를 내려면 증폭기 쪽을 따로 손봐야 한다. 피에조를 남는 핀에 물릴 수 있게 되면
그 번호를 `PIN_BUZZER` 에 적으면 그대로 살아난다.
